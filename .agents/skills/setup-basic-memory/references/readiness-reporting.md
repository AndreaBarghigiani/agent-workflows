## Reporting installation and Basic Memory readiness

Report installation, local routing, live access, retrieval, and schema readiness as separate results. For each applicable result, state its status, observed evidence, tested target (including client, service, project, and read scope when relevant), and the next step for any gap. Use **passed**, **failed**, **unverified**, or **not applicable** accurately; local helper output supports only local installation or routing claims.

A successful query with no matching notes is successful empty retrieval, not a connection failure. Say which project and read scope were queried. A retrieved note proves retrieval only for that tested context. Evidence from one project, client, machine, or service does not establish another's readiness. Reuse a result only while its target, identity, environment, and execution context remain the same.

Distinguish an unavailable MCP tool or connection from an unreadable or missing schema and from a schema that is missing but cannot be created because write authorization is absent. Report schema readiness only from schema read-back and any validation actually performed. Do not propose or perform writes without existing authorization.

If memory is explicitly declined, mark memory results not applicable briefly; do not install or discover memory skills, add memory routing or persistent memory guidance, or probe MCP. An absent choice is unknown, not a decline. For enabled memory, missing routing or unavailable live tools leaves memory setup incomplete but does not invalidate a successful toolkit installation. Routine updates do not gain live access prerequisites or remote writes.

Report a client's MCP configuration as its own result: an entry that exists and points to the intended endpoint is configured, not live. Name the client, scope, and endpoint, and say whether it was reused, added under authorization, conflicting, or deferred. Live access is reported only from a native project-scoped read in that client. Health checks that show a reachable or connected endpoint are network evidence, not memory access.

Keep T3 action registration, execution, and discovery evidence separate from Basic Memory access evidence.
